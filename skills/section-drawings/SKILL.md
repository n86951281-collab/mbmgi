# 平縱橫斷面出圖產生器

本 SKILL 負責全域規則「平縱橫斷面至挖填方、混凝土量作業流程」的前四個階段：收資料、建地形、定線、切原地形縱橫斷面並出圖。
另有兩個分支：整地面 SG 地形（有整地 DWG 時，見「3-1」）、依使用者手改橫斷面修正原地形 EG（見「使用者在 CAD 手調後」）。
名詞：EG＝原地形（測量 TIN）；SG＝整地後地形（EG 套入整地面）。
設計斷面、挖填方、混凝土量（階段五以後）尚未做成程式，照全域規則逐步做。
圖層、線型、圖筆、字級以全域規則「出圖設定表（樣板 v4.0）」為準；程式已照該表寫好，不要自行改動。

## 環境

- Python 需有 numpy、ezdxf、matplotlib。一律用 `python -I` 執行，並先設 `$env:PYTHONIOENCODING='utf-8'`。
- 程式在本 SKILL 的 `scripts/`；圖筆 CTB 在 `assets/plot-styles/`（由 `sync-rules.ps1` 從 mbmgi 倉庫複製）。
- 預覽字型：微軟正黑體 Light（`C:\Windows\Fonts\msjhl.ttc`）、GENISO（`C:\Windows\Fonts\GENISO.ttf`）；這台沒有就在設定檔 `fonts` 指定。

## 步驟

### 1. 收資料，建案件設定檔
1. 每個案件開一個資料夾（例：`D:\Claude_工作區\共用\地形出圖\cases\<案名>\`），從 `templates/case_config.example.json` 複製成 `case_config.json`。**案件設定檔與中間資料只放本機，不放進 mbmgi 倉庫（公開）。**
2. 用 ezdxf 列出測量圖的圖層、各圖層圖元數、有無 Z 值，回報使用者，並請使用者確認：
   - 首曲線、計曲線圖層（`layers.contour_minor`／`contour_major`）。
   - 高程點 INSERT 所在圖層（`layers.spot_insert_layer`，插入點 Z 需大於 0）。
   - 地物圖層（`layers.features`，不帶 Z，只畫在平面圖上）。
   - 圖例表所在圖層與範圍（`legend.layer`、`legend.box`，世界座標 x0, y0, x1, y1）。
3. 依收到的資料選分支，回報使用者：
   - 有等高線（＋高程點）→ 步驟 2。
   - 只有高程點、沒有等高線（`contour_minor`／`contour_major` 留空字串）→ 步驟 2-B。
   - 另有整地 DWG（整地範圍與四角或分區高程）→ 定線後加做步驟 3-1。
   - 這時還沒有整地 DWG 也沒關係，定線確認後的「步驟 3-0」一定會再問一次。
   - 只拿到 DWG 時，複製到純英文路徑，用 SKILL `cadastre-overlay` 的 `scripts/make_scr.py dxfout` 產生指令檔，交給 `accoreconsole.exe` 轉 DXF（指令 `_.DXFOUT "<路徑>" _V 2018 16`）。路徑有中文會轉檔失敗。

### 2. 建地形 ★停點
```
python -I scripts/build_terrain.py <case_config.json>
```
- 等高線沿線每 `terrain.densify_step`（1 m）加密取點，加上高程點建 TIN；邊長超過 `terrain.max_edge`（40 m）的三角形當作測量範圍外刪除。兩個值依全域規則，不要自行改。
- 同時用「只有等高線的 TIN」比對高程點，抽驗結果寫在 `<tin>_qa.txt`（RMSE、MAE、最大誤差、誤差最大 5 點）。把抽驗結果回報使用者；容許誤差尚未定案，不要自己判定合不合格。
- 預覽：
```
python -I scripts/terrain_views.py <case_config.json>
```
  輸出四個正向＋四個斜角的立體圖，格網 `terrain.view_grid_step`（0.1 m，依全域規則），等高線畫進地表顏色裡（背面自然遮住），測量範圍外不畫。把 PNG 給使用者確認後才往下。

### 2-B. 只有高程點時建地形 ★停點
測量圖沒有等高線（例：P33 只有 715 個高程點）時，`build_terrain.py` 會停在「找不到等高線」，改用下列兩支。邊長 40 m 刪三角形、範圍外不內插，同全域規則第 2 階段。
1. 先看高程點代碼分布，找出非路面點：
```
python -I scripts/spot_codes.py <case_config.json>
```
   - 列出每個代碼（屬性 `terrain.spot_desc_tag`，預設 `DESC`）的點數、離參考線偏距、相對參考線高差，以及依偏距分箱的高差。參考線用 `terrain.spot_ref_line`，空白時取定線中心線兩端（還沒定線時一定要填）。
   - 相對高差常態 +1.5 m 以上的代碼多半是擋牆頂、屋台，常態 −0.6 m 以下的多半是既有溝底。代碼意義依測量公司圖例，**先問使用者**，確認後才寫進 `terrain.spot_exclude_codes`；沒確認就不剔除。
2. 建 TIN 並抽驗：
```
python -I scripts/build_terrain_spots.py <case_config.json>
```
   - 沒有等高線可比對，改用留一法（每次拿掉一點，由其餘點內插，再和該點比對），結果寫在 `<tin>_qa.txt`：RMSE、MAE、P90、最大誤差、誤差最大 5 點，以及屬性高程（`ELEV`）與插入點 Z 的最大差。容許誤差尚未定案，只回報、不判定。
   - 誤差最大的點通常就是擋牆頂、溝底這類非路面點（P33：未剔除 RMSE 0.559 m、最大 3.71 m；試剔除 300／301／31188／30031188 四個代碼後 RMSE 0.445 m）。
   - 預覽同步驟 2 的 `terrain_views.py`（等高線由 TIN 取樣畫出，不需要原圖等高線），給使用者確認後才往下。

### 3. 定線 ★停點
- 使用者給定線時，請使用者把中心線、右岸線、左岸線（面向下游）分別放在設定檔 `alignment` 指定的圖層，另存 DXF。
- 使用者沒給定線時，依全域規則用兩岸線中點畫中心線，畫好請使用者確認，再存成上述格式。
```
python -I scripts/make_alignment.py <case_config.json>
```
- 0K+000 在下游：程式比較中心線兩端的 TIN 高程，自動把低的一端當起點；要強制指定時設 `alignment.downstream` 為 `"start"` 或 `"end"`。
- 斷面每 `alignment.spacing`（20 m）一刀，起終點加刀；新舊結構交接面等加刀位置寫在 `alignment.extra_stations`。
- 岸線可以是多段，程式會自動接起來；接完會檢查左右岸是否放反。
- 回報全長、斷面刀數與樁號範圍，等使用者確認。

### 3-0. 問設計地面用 EG 或 SG ★停點（每案必問，不可略過）
定線確認後、開始設計縱橫斷面之前，一定要停下來問使用者，不可自行假設用 EG：
- 「有沒有整地圖（SG）？設計縱、橫斷面要用原地形 EG，還是整地後的 SG？」
- 同時說明差別：構造物頂（溝頂、井頂）貼哪一個面、挖深與開挖面積從哪一個面往下算、縱斷面資料帶標「地面高」或「SG地面高」。
- 使用者給整地 DWG 或整地高程 → 步驟 3-1。
- 使用者說用 EG → 設定檔不加 `sg`，設計出圖用 EG，並在回報與圖說註明「地面採原地形 EG」。
- 使用者還不確定 → 先停在這裡，不做設計縱橫斷面與挖填數量。

### 3-1. 整地面 SG 地形（有整地 DWG 時）★停點
1. 整地 DWG 轉 DXF（純英文路徑，見步驟 1），用 ezdxf 列出圖層與圖元，找出整地框（每區一個四邊形）與標示的高程文字。回報框的尺寸與位置，**四角或分區高程要使用者逐角確認**（西北、東北、西南、東南；北在上）。
2. 在設定檔加 `sg` 區塊：從 `templates/case_config.example.json` 的 `_sg_範例` 複製並改名為 `sg`。
   - `pads`：每區 `{"layer": 圖層, "corner_z": {"NW", "NE", "SW", "SE"}}`（四角雙線性內插），或 `{"layer": 圖層, "z": 高程}`（平整面）。同一圖層的頂點去重後要剛好 4 點；多個分區放不同圖層，不可重疊。
   - `eg_tin_npz`：原地形 EG（空白時用 `tin_npz`）；`tin_npz`：SG 輸出檔名（加版次）。
3. 執行：
```
python -I scripts/build_sg.py <case_config.json>
```
   - 刪除框內及框外 `edge_buffer`（1 m）內的原高程點，框內補 1 m 格點、框線每 0.5 m 補點，高程取整地面，再重建 TIN（40 m 規則同 EG）。
   - 開頭會印出原地形在四個角點的高程，和給定高程差很多時，先和使用者確認角點有沒有對錯。
   - `<sg>_qa.txt`：SG 與整地面理論值最大差（框內密取樣超過 0.01 m 會停下來）、整地面－原地形（最小、最大、平均、填方面積比）。
   - 同時輸出 `profile_<圖層>_SG.csv`：定線各線每 1 m 的 SG 高程、原地形高程、整地差。
4. 回報 QA 與定線起終點 SG 高程，等使用者確認後，設計縱、橫斷面一律改用 SG（見下節「設計出圖用 SG 地面」）。

### 4. 出圖
1. 填設定檔 `plan`：
   - `center_world`：平面圖中心的世界座標（通常取定線範圍的中點）。
   - `ticks_e`、`ticks_n`：圖廓邊的 TWD97 座標刻度（每 50 m，取落在圖廓內的整數）。
   - `frame`、`center_paper` 一般不用改（1/1000、圖廓 170×237 mm）。定線範圍超過 170 m × 237 m 時，1/1000 放不下，回報使用者決定分幅。
2. `profile.split_at`：縱斷面分張樁號，每張約 120 m（例：全長 228.9 m → `[120]`）。
3. 執行：
```
python -I scripts/section_drawings.py <case_config.json>
```
4. 看執行紀錄的「[檢查]」：每張圖的文字壓線、文字重疊、出界都要是 0 處；不是 0 就調整位置參數或回報使用者。「樁號未能避開」也要處理。
5. 輸出（檔名開頭都是 `file_prefix` 加存檔時間）：
   - `out_dir`：`…_A3_縱橫斷面圖說_<version>_TWD97_GENIE.dxf`（所有圖紙橫向並排，每張間隔 450 mm）、同名 PDF（套圖筆）。
   - `preview_dir`：每張圖一份 PNG，給手機檢視。
6. 要 DWG 時，用 AutoCAD 的 `accoreconsole.exe` 跑腳本 `FILEDIA 0` → `_.SAVEAS 2018 <路徑>` → `_.QUIT _Y`，路徑要純英文。

## 設計圖冊（平面配置、平縱斷面、橫斷面、標準圖）

設計階段的圖冊版面與標註依 CLAUDE.md「四、CAD 與 DXF 圖面 > 設計圖冊版面與標註規則 v2」辦理；組圖、引用他機關標準圖、封面、PDF 合併、CAD 整合發布的程式與步驟見 SKILL `drawing-set`。

### 設計出圖用 SG 地面（設定檔有 `sg` 時）
設計縱、橫斷面產生器（P33 為案件夾的 `design_profiles.py`、`cross_sections.py`，尚未搬進本 SKILL）以「設定檔有 `sg`」判定改用 SG：
- 地面高程一律取 `sg.tin_npz`。縱斷面資料帶的「地面高」改標「SG地面高」，橫斷面說明寫「挖方以 SG 地面高程計」「地面線為 SG 整地後地面」。
- 構造物頂貼 SG：側溝（含蓋板）頂、集水井蓋板頂要貼 SG 時（P33 使用者 2026-11-05 指示），沿線每 1 m **逐點**取 SG：蓋板頂＝SG、溝牆頂＝SG－蓋板厚、溝底＝溝牆頂－內淨高。**不要用 polyfit 把溝頂拉成一條直線**：直線會在 SG 起伏處高出或低於地面。縱坡只用來回報，資料帶坡度逐段計算。
- 原地形線開關 `sg.draw_eg_line`：`{"profile": false, "cross_section": false}`（預設，照 P33 使用者決定：縱、橫斷面都拿掉原地形線，只畫 SG）。改成 `true` 時，該圖另以「原始地面線」圖層（252、DOT2）畫 EG 當對照，圖例加「原地形」。沒有這個鍵時視同 `false`。
- 「先整地到 SG 再開挖」對挖深的影響：
  - 挖深、開挖面積都從 SG 往下算（挖深＝SG－開挖底）。構造物頂貼 SG 時挖深是常數（P33：蓋板 23 cm＋內淨 100 cm＋底版 20 cm＋墊層 10 cm＝1.53 m）。
  - 整地本身的挖填（EG→SG）另算，不含在構造物開挖裡；SG 低於 EG 處，實際從現地往下挖的深度＝整地挖深＋構造物挖深。整地土方的算法與列項【待確認】，先問使用者。
  - 開挖寬超出整地框時，框外是 EG，斷面會碰到框外擋牆、屋台而面積變大（P33 B 側 0K+100 挖方 3.24 m²，其他刀約 3.05 m²）。要回報使用者決定加寬整地框或接受。

## 使用者在 CAD 手調後

使用者回傳 DWG：轉 DXF（`accoreconsole.exe` 跑 `DXFOUT`），和這次輸出的 DXF 逐圖元比對，把差異寫回 `scripts/section_drawings.py` 或樣板，開 PR 更新 mbmgi，並升版號。比對差異見 SKILL `cad-v2-feedback`。

### 手改橫斷面地面線 → 修正原地形 EG ★停點
使用者在 V2 橫斷面改了地面線（例：P33 把整地框外的擋牆、屋台突起壓平）並要求「回饋到 EG、全域修正」時：
1. 由 V2 比對取出各刀地面線，存成 `edits_npy`（格式見 `scripts/eg_fix.py` 檔頭；`user` 要含沒改的刀，內插才有錨點）。比對差異見 SKILL `cad-v2-feedback`。
2. 從 `_eg_fix_範例` 複製並改名為 `eg_fix`，填 `edits_npy`、`src_tin`、`out_tin`（加版次）、修正帶 `band`（兩側橫距 [內, 外]）、`s_range`。
3. 執行：
```
python -I scripts/eg_fix.py <case_config.json>
```
   - 各刀取 dz＝使用者線－原 EG，刀與刀之間依樁距線性內插，修正帶內刪原點改放 0.5 m 格點，重建 EG。修正帶以外不動。
   - `<out_tin>_qa.txt`：各刀修正帶內新 EG 與使用者線最大差（P33 七刀 0.000～0.107 m）。回報使用者。
4. 把 `tin_npz`（或 `sg.eg_tin_npz`）改指向新 EG，`sg.tin_npz` 升版，重跑 `build_sg.py` 與設計出圖；縱、橫斷面、數量都要跟著重算。

## 踩過的雷

- **縱斷面原地形線跳動**：只有高程點、沒有篩選時，EG 含擋牆頂、屋台、既有溝底點。副定線離道路中心線約 4.3～4.7 m，剛好壓在路邊既有側溝、擋牆上，沿線取的 EG 會往下掉約 1 m（溝底）或往上衝出圖框（擋牆頂，P33 B 線與路面差 −0.97～+2.40 m）。SG 線是平順的，設計數值不受影響；P33 使用者決定縱、橫斷面都拿掉原地形線（`sg.draw_eg_line` 預設 `false`）。要保留對照時，改畫只用路面點建的 EG（剔除代碼或與中心線高差 > 0.25 m 的點）。
- **SG 框邊下凹**：只刪框內原點時，框外緊鄰框邊的原點和框內點連成的三角形會跨進框內，把整地面拉低（P33 v1 A 側最後 1 m 凹 0.1 m，縱坡變成 −0.25%）。已改為框外 1 m 內的原點一起刪（`edge_buffer`），並用框內密取樣檢核。
- **四角高程對錯角**：P33 使用者第一次口述的四角高程和最後確認的不同（例：口述左上 478.7，確認西北 476.99）。用原地形在四個角點的高程比對，差很大就先問，確認後寫進 `sg.note`。
- **溝頂用 polyfit 拉直線**：溝頂要貼 SG 時，直線會讓蓋板頂高出或低於地面；改成逐點取 SG。
- **DWG 轉檔路徑**：accoreconsole 在中文路徑會轉檔失敗，複製到純英文資料夾再轉。
- **EG 修正的 dz 要對 EG 本身取**：出圖的原地面線可能在框頂被截斷，拿出圖線當基準會算錯；`eg_fix.py` 一律用 EG TIN 在同一點的高程。
- **EG 改了要連動**：EG 修正後 SG、縱斷面、橫斷面、挖填數量都要重算並升版（全域規則「工作方式規則 > 二、一致性與連動」）。

## 已知限制

- 設計線、挖填方面積、混凝土量還沒做：橫斷面上的「挖：— m²　填：— m²」是預留位置；縱斷面圖例的「計畫溪床線（待設計）」亦同。
- 切線用前後各 1 m 求差分。2026-11-01 中心線1 案當時的算法沒有保留，用這支程式重算會有 0～1.9 度的差異；該案沿用原本的 `alignment.npz`，不要重算。
- 中心線1 案的 TIN 是當時用等高線加密 2 m 建的（2026-11-04 才定為 1 m）；該案沿用原本的 `tin.npz`，要改用 1 m 重建須先問使用者。
- 中間檔（`tin_npz`、`alignment_npz`）與出圖 DXF 已存在時程式會停下來，不覆蓋；重算請在設定檔改檔名加版次。
- 立體預覽在陡坎、測量範圍邊緣會有格網鋸齒，是預覽用格網的解析度限制，不影響 TIN 與斷面（斷面直接由 TIN 取高程）。
- `section_drawings.py`（原地形縱橫斷面）不讀 `sg`，仍畫 EG；SG 版的設計縱、橫斷面產生器目前在 P33 案件夾，還沒通用化進本 SKILL。
- `build_sg.py` 以框中心分西北、東北、西南、東南四角，整地框轉角接近 45 度時分不出來會停下；整地面只支援四角雙線性與平整面，坡面、分區不規則多邊形尚未支援。
- `eg_fix.py` 在第一刀之前、最後一刀之後的樁距（例：P33 樁距 −5～0 m）以最近兩刀線性外插 dz。
- `build_terrain_spots.py` 的留一法每點重建一次三角網，715 點約 6 秒；點數上萬時要跑很久。
