# CAD 手改圖回饋（V2 回寫）

規則以 CLAUDE.md 為準，本 SKILL 只講程式與步驟：
- 「四、CAD 與 DXF 圖面」出圖與回饋末條：手調後回傳 DWG → 轉 DXF 逐圖元比對 → 寫回產生器與樣板 → 升版號。
- 「工作方式規則」一（字面指示照做；圖上數值和口頭指示衝突先問，不擇一照改）、二（改共用元件搜全部產生器）、三（內容有變就升版次、存檔時間用 `Get-Date`）、四（交付前用 PUBLISH 的 PDF 目視）。
- 版面規則寫到哪：「設計圖冊版面與標註規則 v2」（設計階段 A3 圖冊）或「出圖設定表（樣板 v4.0）」（測量、斷面階段）。

P33 東山街案的四輪 V2 回饋（2026-11-05～06：橫斷面版面、地形、縱斷面、橫斷面標註）是本 SKILL 的來源；案件資料夾 `D:\Claude_工作區\共用\地形出圖\cases\P33_新社東山\eg_fix.py` 是「V2 改地面線 → 回饋 EG 地形」的例子。

## 環境
- Python 3.12＋numpy、ezdxf、matplotlib；執行前設 `PYTHONIOENCODING=utf-8`。比對程式讀的是使用者回傳的檔，加 `-I`。
- AutoCAD 2022 `accoreconsole.exe`（`C:\Program Files\Autodesk\AutoCAD 2022\`）：DWG 轉 DXF。沒裝 AutoCAD 的機器請使用者自己存 DXF（2018）。

## 模組
| 檔案 | 用途 |
|---|---|
| `scripts/run_dxfout.ps1` | DWG 轉 DXF 一條龍：複製到純英數暫存資料夾 → 產生指令檔 → 跑 accoreconsole（逾時就結束程序）→ 檢查有輸出 → 複製到指定位置。原檔只讀。檔案內容只用 ASCII（PowerShell 5.1 讀無 BOM 的 .ps1 會當 ANSI） |
| `scripts/make_dxfout_scr.py` | 產生 DXFOUT 指令檔（`FILEDIA 0`、`DXFOUT "<路徑>" _V 2018 16`、`QUIT _Y`；ASCII、CRLF）。路徑含中文或 `~` 直接停止 |
| `scripts/dxf_diff.py` | 兩版 DXF 逐圖元比對，輸出 `diff.csv`、`diff_summary.txt`、`diff.png`、`diff_zoom.png` |

### dxf_diff.py
```
python -I dxf_diff.py <基準.dxf> <V2.dxf> <輸出資料夾> [--tol 0.01] [--move-max 100]
       [--layers 文字,標註*] [--ignore-layers 格線] [--space model|paper|all] [--explode]
       [--upm 10] [--upm-y 20] [--window x0,y0,x1,y1] [--prefix diff]
```
- `--tol`：座標容差（圖面單位，A3 圖紙是 mm）。產生器與 DXFOUT 的誤差在 0.001 以下，預設 0.01。
- `--move-max`：「移動」配對的最大距離；同內容的文字不受此限（依內容配對）。
- `--upm`：圖面單位／實際公尺，有給就換算實長。例：橫斷面 1/100（mm）→ 10；1/300 → 3.333；縱斷面 H1/500、V1/50 → `--upm 2 --upm-y 20`。
- `--explode`：圖塊參考展開再比（使用者改了圖塊內容時用）；預設把 INSERT 當一個圖元。
- 比對順序：完全相同 → 原位改屬性（圖層、文字、字高、顏色線型）→ 平移（形狀相同）→ 同內容文字遠距搬移 → 文字改內容＋小幅移動 → 同圖層的線改形狀 → 其餘算刪除、新增。
- 重複圖元（格線、刻度）會先找「主要位移量」再重配，避免配到隔壁那條；仍可能剩少數錯配（P33 實測：格線出現 −1.812 與 +18.188 兩組，差一格 20 mm），以最大群組為準。
- 摘要的「共同位移群組」：一群圖元用同一個位移量一起動，通常就是一條版面規則（例：整框上移 18 mm）。
- 形狀改變列出兩個方向的偏差：「V2→基準」小、「基準→V2」大，表示只是截短或刪點；兩個都大才是真的改了線形（例：地面線改高程）。
- 預覽圖：灰＝未變、紅＝刪除、紅虛線＝移動前或改形前、綠＝新增或移動後、橙＝改形後、藍＝原位改屬性、紫箭頭＝移動方向。

## 步驟

### 1. 收檔
- 找 V2：先找本機 `D:\Claude_工作區\輸出\<案件>`（含 `OLD\`），檔名通常是產生器檔名加 `__V2` 或 `_V2`；再找 NAS。
- 找基準：V2 檔名裡的存檔時間與版次就是它的基準（例：`20261105_2046_…_v1.4…__V2.dwg` 對 `20261105_2046_…_v1.4….dxf`）。基準和目前產生器版次不同時，先比 V2 對基準，再看目前版本是否已含這些改動。
- 轉檔（NAS、使用者原檔只讀）：
  ```
  powershell -ExecutionPolicy Bypass -File run_dxfout.ps1 -Dwg "<V2.dwg>" -OutDxf "<暫存>\v2.dxf" -Work D:\cadtmp\v2fb -TimeoutSec 180
  ```
  `-Work` 要純英數、不含 `~`；`-Dwg`、`-OutDxf` 可以有中文（只用 PowerShell 複製，不經過 accoreconsole）。

### 2. 比對
- 先跑全圖：`python -I dxf_diff.py <基準.dxf> <v2.dxf> <暫存>\diff --upm <比例>`。
- 看 `diff_summary.txt` 的各類筆數、逐圖層統計、共同位移群組；再看 `diff_zoom.png`。差異多時用 `--layers` 分圖層各跑一次（例：只看「文字,標註」）。
- 使用者只示範一兩處（P33：11 刀只改了 0K+000、0K+040 兩刀）時，找出那幾處的共同改法，再判斷是否套用全部；判斷不出就問。
- MLEADER 的字高、文字、引線端點都會比；V2 新增的 MLEADER 會列在「新增」，要逐條讀文字內容（例：「臨時擋土／鋼軌樁L=6@1m」）。

### 3. 歸納
把每一類差異分成兩種，填成表（類別、圖層、差異、出現處數、判斷）：

| 分類 | 例（P33） | 處理 |
|---|---|---|
| 規則：版面 | 斷面框上移 18 mm；CL 移到框上方；樁號移到框下方置中加底線；縱斷面框改從資料欄起 | 寫進產生器，全部斷面／全部圖套用 |
| 規則：標註格式 | 面積兩行靠右排在樁號下方；多重引線「新設側溝式箱涵／W×H=…／渠底EL+…」；集水井改標「內徑」 | 寫進產生器；字高低於 14 pt 的照 CLAUDE.md 改回 14 pt，回報時說明 |
| 規則：樁位、資料帶順序 | 資料帶「樁號」移到「單距」上面；鋼軌樁打在既有側溝外緣線 | 寫進共用模組 |
| 規則：刪除 | 框內豎格線刪掉 | 產生器不畫 |
| 數值 | 鋼軌樁 L=6、集水井內移 0.32～0.37 m、地面線改高程 | 和口頭指示、先前定案逐項比；不同就列出來先問（下節），不擇一照改 |
| 手調誤差 | 移動量和規則值差幾公分（0.32～0.37 m vs 規則 0.30 m） | 以規則為準，回報偏差量 |

- **數值衝突先問**：V2 圖上的數值和使用者口頭指示或先前定案不同時（P33：V2 寫 L=6，口頭說「打設深度約 3 m」），列出兩個值與出處，先問。P33 當時先照 6 m 全冊改了才問，使用者回「打 3 米」，又全部改回，這就是要避免的。
- 地形類改動（地面線改高程）不是版面規則：回饋到 TIN（參考 `eg_fix.py`：取各斷面 dz、樁號間內插、重建 TIN），重建後和 V2 線比對差異（P33：0.1 m 以內），挖填方、數量全部重算。
- 使用者的 V2 字高、線型若違反 CLAUDE.md（例如引線字高 3 mm），規則優先，但回報時要講。

### 4. 寫回
- 改產生器與樣板；共用元件（圖框、`p33_sheet.py` 的 mleader、字寬、圖層、集水井位置）先 `grep` 所有產生器與呼叫處，每一處都改到（工作方式規則二）。P33 例：集水井內移 30 cm 寫進平面共用模組後，平面圖、縱斷面平面帶、地籍圖、放樣座標表、一般說明、S-03 都要跟著改。
- 改 `.py` 用 Edit 工具或 Python 讀寫（`encoding="utf-8"`），不要用 PowerShell 的 `Set-Content`／`-replace` 改中文程式。
- 升版次（工作方式規則三），存檔時間用 `Get-Date`；舊版移 `OLD`。
- 重出後再比一次：`python -I dxf_diff.py <新版.dxf> <v2.dxf> <暫存>\diff_after`。殘餘差異應只剩：
  - 使用者手調的非規則項（例：手拉的位置差幾 mm）；
  - 刻意不照 V2 的項目（字高改回 14 pt、數值衝突待問、規則值取代手調誤差）。
  其他殘餘差異逐項說明或再修。新版 DXF 的座標若整體平移過（例：框上移），用 `--window` 或 `--layers` 只比要檢查的區塊。
- 跑產生器的自動檢查（重疊、壓線、出界、引線壓字、字級）全 0；用 PUBLISH 發布 PDF 目視。

### 5. 回報
依序：
1. 差異統計：基準與 V2 檔名、圖元數、各類筆數（例：移動 63、形狀改變 5、新增 2、刪除 2）。
2. 歸納出的規則：每條寫成一句可執行的規則，並建議寫進 CLAUDE.md 哪一節（例：「設計圖冊版面與標註規則 v2 > 橫斷面圖（X）」）。規則要另開 PR 改 CLAUDE.md，不在回寫對話裡直接改。
3. 偏差量：手調值 vs 規則值（例：集水井內移 0.32～0.37 m vs 規則 0.30 m，以規則為準）。
4. 待問事項：數值衝突（例：L=6 vs 3 m）、使用者只示範一處而不確定要不要全套的改法。
5. 新檔名與版次；提醒使用者下次手改請用新版 DXF 來改，才對得上。

## 踩過的雷（2026-11-05～06 P33 實測）
- accoreconsole 路徑有中文會變成「?」，找不到檔就卡在提示等輸入。DWG 一律先複製到純英數資料夾（例 `D:\cadtmp\v2fb\src.dwg`）再轉。
- accoreconsole 卡住不會自己結束：用 `Start-Process -PassThru` 加 `WaitForExit(秒數)`，逾時就 `Kill()`（`run_dxfout.ps1` 已處理），不要讓工具呼叫掛著等。
- `ADMINI~1` 這類短檔名 accoreconsole 讀不到；scratchpad 路徑要用 `[IO.Path]::GetFullPath` 或 `(Get-Item …).FullName` 展開成 `C:\Users\Administrator\…`。
- DXFOUT 版本關鍵字用 `2018`（`_V 2018 16`）；指令檔用 ASCII、CRLF。
- 用 PowerShell 改 `.py`（`Get-Content | Set-Content`、`-replace`）會把中文弄亂（5.1 預設 ANSI）；改程式用 Edit 工具或 Python。
- 讀案件 `case_config.json` 等 json 用 `encoding="utf-8-sig"`：PowerShell 寫的 UTF-8 有 BOM，`utf-8` 會報錯。
- AutoCAD 存回的 DXF 線型名稱大小寫會變（`CONTINUOUS` → `Continuous`），比對時已忽略大小寫，不算圖層改變。
- 舊比對法（依座標四捨五入當鍵值）把整框搬 18 mm 的改動報成大量刪除＋新增（當時 `xs_diff.txt`：REMOVED 70），看不出規則；改用平移配對＋共同位移群組後，直接看出「186 筆一起上移 18 mm」。
- 使用者手改的檔可能是從舊版改的（P33：V2 從 v1.4 改，當時產生器已到 v1.5）；一定用 V2 檔名對應的那一版當基準。
